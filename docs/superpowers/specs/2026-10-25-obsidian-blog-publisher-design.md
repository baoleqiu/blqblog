# Obsidian 博客发布插件：第一版设计

日期：2026-10-25。状态：用户已确认并授权开发；实现按配套实施计划推进。

## 1. 目标与使用方式

用户只在 Obsidian 写作，在同一个发布界面填写博客信息、查看真实博客效果并发布。继续使用现有 Firefly / Astro 博客、GitHub 和 Vercel，不要求用户手工复制 Markdown、寻找附件目录或执行 Git 命令。

默认点击 Obsidian 左侧“博客”入口后左右分屏：左侧原笔记，右侧独立“博客发布”标签页。右侧是插件视图，不是 Markdown 笔记，不在普通目录生成“发布页面.md”。右侧绑定打开它时选中的笔记；切换到其他笔记不改变目标，主动选择“切换到当前笔记”才重新绑定。

停止输入后自动更新本地预览；保留“刷新预览”和“在浏览器打开”入口。首次启动预览服务允许较慢，过程中显示可理解的进度。保存笔记、修改发布信息、打开或刷新预览均不推送 GitHub，不部署网站。

## 2. 已确认的要求与范围

- Windows 这台电脑优先；专用本地插件，无需购买 Obsidian Publish。
- 从库内任意 Markdown 笔记发布，不要求移动到博客专用笔记目录。
- 发布整篇已经整理的笔记；不做私密段落标记、AI 改写或自动内容筛选。
- 标题、分类、标签、摘要、封面、发布日期在发布面板填写；保存在插件数据中，不写回源笔记。
- 最终导出的博客文章使用标准顶部属性 `category` / `tags`；正文零散 `#标签` 不自动收集。
- 先支持七类内容：基础 Markdown 排版、数学公式、普通代码块、高亮、提示框、图片双链、普通笔记双链。
- 笔记嵌入和 Dataview / Tasks 等动态查询不属于第一版自动转换范围。
- 原图完整保留；网页使用展示图，提供查看原图入口。
- 已发布旧文章保持现状；第一版用《小鼠脾脏 CD8 T细胞提取》验证流程。
- 源笔记删除后线上文章保留；插件提供独立“下架”操作，操作本身不删除 Obsidian 原稿。
- 现有网站加载速度、相册、壁纸、字体、音乐的诊断和优化延期，不混入本次实现。

第一版明确不包含手机端发布、多人协作、定时发布、文章批量发布、自动迁移旧文章，以及任意 Obsidian 社区插件内容的运行环境。

## 3. Approaches：考虑过的方案

| 方案 | 取舍 | 决定 |
| --- | --- | --- |
| Buttons / Templater 等现有插件加脚本 | 入口较快搭建，但转换、状态和错误反馈分散，需要维护多个配置 | 未选 |
| 专用本地插件及本地发布程序 | 初期实现较多，可把填写、预览、发布记录和失败恢复放在统一界面 | 用户已选 |

界面填写与数据存放分开考虑。自动写回源笔记顶部的方案已讨论，用户明确选择插件单独保存博客信息，保持原笔记简洁。

## 4. 发布面板及元数据

顶部始终显示绑定笔记、发布状态和目标网站。字段区显示标题、一个分类、多个标签、摘要、封面和发布日期。预览区加载博客实际页面，并与 Obsidian 插件界面的样式隔离。

以下为实现建议，供本设计确认；不是额外声称用户已逐项指定：

- 首次选择笔记时，从其已有顶部属性读取适配的字段作为初始值；没有标题则用文件名。之后以插件保存值为准，不在两个位置双向同步。可提供“重新从笔记读取属性”，明确显示其会覆盖面板中哪些值。
- 分类提供现有博客分类建议，也可输入新分类；标签可多选和输入。分类、标签、摘要和封面允许为空，空值在面板清楚显示。
- 首次发布日期为空时，发布前在面板填入本机当天日期；允许历史日期。第一版不支持未来定时发布，不能把填写未来日期解释成预约上线。
- 更新时保持首次发布日期，除非用户主动修改该字段；成功更新记录 `updated` 日期。
- 首版封面从当前笔记图片或库内用户主动选择的图片中选取，可清除；不自动选择私人图片。跨库外文件和剪贴板封面导入可留给后续版本。
- 面板字段变化自动保存到插件数据，并参与预览刷新。关闭页面、重启 Obsidian 后可恢复。
- 源笔记的顶部属性不会作为正文展示；只把明确映射的博客字段写入导出稿，不复制其他笔记属性。
- 正文内容保留原文。若正文开头已有一级标题，第一版保留，不静默删除可能有意义的标题；预览呈现实际结果。

面板主按钮随状态变为“发布到网站”“更新线上文章”或“已是最新”。发布目标和当前变更在点击前可见；正常发布不额外叠加一次通用确认弹窗。下架是独立操作，显示目标文章并要求明确确认。

## 5. 数据与文章身份

插件使用标准的本地数据文件保存设置、尚未发布的文章信息及发布记录；这些数据不整体提交到博客仓库。采用版本化数据结构、写入校验和上一份可恢复备份，提供发布设置与记录的导入、导出功能。备份不包含 Git 凭据。

每个受管理笔记分配稳定的内部 articleId，保存相对库路径、固定博客路径、元数据、已预览指纹、最近提交、最近上线版本和操作状态。articleId 不写入源笔记。笔记改名/移动通过 Obsidian 事件更新关联，博客网址不随文件名或标题自动变化。

未运行插件期间发生改名或移动、源文件删除、重新安装后缺少记录时，不靠同名或相似正文自动认领。显示“原笔记未找到”，允许用户明确重新关联；原线上文章继续保留。导入记录检查库和博客身份，存在冲突先展示，不自动覆盖。

已发布文章对应的公开导出记录只包含 articleId、博客路径、输出资产清单、公开元数据、操作版本等必要信息，不包含 Obsidian 本地绝对路径或其他草稿。它用于验证生成文件归属和恢复发布对应关系，不作为源笔记备份。

建议保留一个简洁发布记录列表：标题、未发布/待更新/上线确认中/已上线/已下架/源笔记缺失状态，以及打开原笔记、打开网站、选择发布目标等操作。它是插件界面，不生成列表 Markdown；第一版只管理插件登记过的文章。

## 6. 内容转换约定

使用 Markdown 语法树或等价的上下文感知处理，不能用无差别替换误处理代码块、行内代码和转义文本。

| 内容 | 第一版行为 |
| --- | --- |
| 标题、段落、表格、列表、任务勾选框、加粗、普通链接、Unicode 上标 | 保留内容及结构，使用博客现有排版 |
| 常用数学公式 | 复用博客现有公式渲染；不支持的命令产生明确问题提示，不能假装渲染成功 |
| 普通代码块 | 保留语言标记、缩进和内容，复用博客代码样式 |
| `==高亮==` | 转成博客支持的高亮标记，保留原文字 |
| 常见提示框 | 复用/适配博客已有 callout 渲染，保留类型、标题、正文和折叠含义；不承诺继承 Obsidian 自定义 CSS |
| 图片双链、已有 Markdown 图片 | 用 Obsidian 的文件解析结果定位图片，复制引用资产、处理别名和宽度，生成有效博客图片引用 |
| 普通笔记双链 | 已知已发布目标转博客链接；未发布目标转显示文字并列入提示，不发布目标笔记 |

普通双链的别名需要保留。目标笔记即使存在同名文件，也必须按源笔记实际解析结果匹配。第一版优先保证文章级链接；段落或块定位若不能可靠映射，退回目标文章链接并提示，不生成伪锚点。已有旧博客文章无可靠源笔记映射时，不靠标题猜测关联。

`![[另一篇笔记]]`、Dataview/Tasks 查询块及不受支持的媒体嵌入必须出现在转换问题列表。第一版遇到会丢失内容的结构时阻止发布，提示在原文中整理成静态内容；不自动遍历引用笔记，也不把动态查询当普通代码发布。代码示例里被转义或明确作为代码展示的语法不触发误报。

预览和发布必须共用同一个转换程序及规则版本。缺失附件、歧义引用、非法元数据是阻断问题；未发布的普通双链降为文字属于非阻断提示。

## 7. 图片与输出文件

导出稿及其附件由程序管理，不要求用户手工维护两份内容。只有明确选中笔记实际引用的图片和封面会被收集，不复制整个附件目录。

建议输出命名空间：文章位于 `src/content/posts/obsidian/<articleId>/index.md`；图片位于 `public/obsidian-published/<articleId>/`，区分 `originals/` 与 `display/`；公开归属与上线版本记录位于单独的发布器命名空间。实现时验证 Astro 最终内容 id 和 URL，不能仅凭文件名推测路由。

- `originals/` 原文件按字节复制并校验摘要；源文件始终不改。文件名使用内容摘要和安全扩展名，避免重名覆盖。
- `display/` 对常见 JPEG/PNG/WebP 生成适合页面的展示图，可复用仓库现有 sharp；不放大小图，保留透明度和合理方向。具体像素尺寸与编码参数由实现者决定并用文字照片检查。
- 每张展示图提供明确可用的原图入口，不能被现有图片灯箱脚本劫持成仍然打开缩略图；实现时验证主题交互。
- GIF/SVG 等无法按常见静态图处理的格式保留原有语义或明确提示，不静默丢动画/内容。视频、PDF等媒体不在本轮七类支持中，遇到嵌入时明确提示。
- 更新仅修改所属文章及已登记资产；移除不再引用的文件前确认它们为该文章独占、且没有手工改动。不清理其他文章的文件。

以上只针对新发布流程生成的图片，不修改旧文章、既有相册、背景、音乐或全站字体配置。

## 8. 真实主题的本地预览

在 `cache/obsidian-publisher/` 等已忽略位置建立临时预览工作目录，使用本机 `E:\blqblog` 当前的 Astro 配置、组件、样式、已发表内容和公开资产，并加入选中文章的临时导出版本。预览修改不进入正式文章目录或 Git 暂存区。

不维护一套长期冻结的预览主题。每次启动核对源版本，运行期间跟踪相关博客代码、绑定笔记、被引用附件和面板元数据变化；增量刷新，必要时重启本地 Astro。主题只在 GitHub 修改而未同步到本机时，界面不能声称本机预览代表远程新主题。

插件界面负责配置和交互；本地 Node 程序负责转换、图片、预览及 Git 操作。进程以参数数组调用，不把笔记内容拼接到 shell 命令。Astro 只监听回环地址；正式发布操作由插件调用本地程序，不暴露给预览网页的匿名 HTTP 接口。

自动刷新使用短暂防抖，合并快速连续编辑，不在每个按键后重启服务。绑定笔记未保存的编辑、面板待保存值必须进入一致快照；旧的异步结果不能覆盖较新的预览。尽可能保留滚动位置；缺失图片等问题要可定位到对应文本。

预览指纹包含正文、发布字段、实际附件内容、转换规则以及相关博客代码版本。发布按钮只有在最新快照已经转换并实际显示成功时可用；预览后内容继续变化则重新生成。锁定的一次发布使用该快照；发布期间的新编辑保留为下一次待更新内容。

关闭视图与退出 Obsidian时，按进程归属清理自己启动的预览资源，不终止用户独立运行的服务。端口占用时选择空闲回环端口，不直接杀占用者。

## 9. 发布、更新、下架与 Git 边界

状态至少区分：本地草稿、待更新、检查/构建中、提交完成待推送、已推送待上线验证、已上线、失败待重试、已下架、原笔记缺失。Git 推送成功不能直接等同于上线成功。

发布/更新流程：

1. 校验绑定目标、最新预览快照、必要信息和附件，检查本地 Git 与上游状态。
2. 在隔离的发布候选目录验证整站生产构建；选中候选文章使用正式可发布状态，测试不把其他草稿带入线上输出。构建失败不推送。
3. 将候选文章及其资产写入本地博客受管目录，核对这批输出及生产构建产物来源。只提交本次文章相关的明确路径；提交信息使用 Conventional Commits。
4. 推送实际配置的上游分支；部署分支首次设置时核实，不从分支名字自动认定它就是 Vercel 生产分支。
5. 验证绑定域名上的本次版本，再显示已上线并提供网址。更新使用同一 articleId/URL；无变化不重复提交。

建议用每次操作的唯一公开版本标记核对线上部署：标记只包含公开 articleId、操作标识和发布/下架状态，不包含笔记正文或本地路径。通过绑定域名读到匹配标记，才能确认该版本被部署。轮询有时间上限，网络失败或超时显示“已推送，尚未确认上线”，可稍后重试，不能报成已上线或凭空判断 Vercel 构建失败。这一方案不要求另存 Vercel 管理令牌。

下架使用同样的构建、精确提交、推送和线上确认流程，删除该文章的受管博客输出及独占资产，并保留下架版本标记。源笔记和插件里的文章信息保留；恢复发布可使用同一网址。下架不清除 Git 历史，也不承诺删除第三方缓存或其他人已保存的副本。

Git 与恢复约束：

- 使用电脑现有 Git 认证；不在插件数据或日志中保存密码、令牌。
- 每次操作重新确认分支、上游和远端进度。本地存在无关待推送提交、暂存改动或远端分歧时暂停并说明，不自动强推、覆盖、合并或夹带提交。
- 未跟踪的无关文件（当前 `.vscode/`、`AGENTS.md`）不加入提交，也不因它们存在就一律阻止发布。与主题渲染有关但尚未提交/同步的代码变化会阻止上线，避免本机预览与实际部署不一致。
- 在受管输出目录检测手工修改，冲突时不覆盖。禁止 `git add -A`、整库重置和清理。
- 操作串行并具有持久化操作记录。推送失败后保留已创建提交并可续传，不重新生成另一篇文章或丢弃用户其他修改。
- 写入/构建失败只回退本操作拥有且未被其他写入改变的文件；无法安全回退时准确显示当前状态，不执行破坏性兜底。

## 10. 第一版验收

以《小鼠脾脏 CD8 T细胞提取》为首个真实验证样本，并补充专用的少量格式测试样本，不在用户原稿中插入测试内容。

- Obsidian 内实测左右分屏、固定目标、面板填写与重启恢复；修改笔记不写入任何博客属性。
- 原笔记和原附件摘要在插件操作前后保持不变；面板数据只存插件目录。
- 七类支持格式有真实渲染验证；嵌入笔记、动态查询、缺图有明确反馈；代码中的伪链接不被改写。
- 通过真实博客主题验证公式、提示框、图片、窄表格；修改主题相关文件后预览跟随更新。
- 原图复制按字节一致，原图入口实际可达，展示图中的实验文字仍可辨认。
- 发布候选必须通过仓库适用生产构建；不把检查脚本产生的无关文件混入文章提交。
- 在临时 Git 仓库中验证精确提交、无关文件、未推送提交、远端分歧、网络失败重试、稳定网址、更新、下架和恢复；这些测试不操作实际线上文章。
- 实际网站的第一次发布只在用户看过最终候选后执行。验证“已推送”和“已上线”状态有真实证据；失败时不会误报成功。
- 删除或改名源笔记，不自动删除线上文章；发布记录视图不生成普通 Markdown 文件。
- 老文章及全站外观不发生本任务之外的变更；网站整体提速继续留待后续。

## 11. 留给实现者的细节与后续步骤

模块拆分、组件组织、数据格式版本号、去抖时长、缓存淘汰、图片尺寸/编码细节、固定 ID 的具体编码以及测试框架由实现者根据现有仓库决定。不得以实现便利改变上述用户要求。

设计审阅应只提出影响实际使用或实现正确性的缺口。处理审阅结果并由用户确认本设计后，再编写实施计划、开发和安装插件；当前临时 CD8 预览不能视为正式插件已经完成。

2026-10-25 独立实施审阅结果：没有重要缺口。用户仍需确认本设计及其中标明的实现建议；本次仅形成设计文档，未安装插件、修改 Obsidian 原稿或发布文章。
