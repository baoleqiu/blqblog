# Obsidian 博客发布器

在 Obsidian 左侧点击纸飞机图标「博客预览与发布」。左侧继续编辑原笔记，右侧是独立的博客工作台，不会在笔记目录生成新 Markdown 文件。

## 日常使用

1. 打开准备发布的笔记，点击纸飞机。面板固定这篇笔记；之后浏览其他笔记不会自动更换目标。需要更换时点击「绑定当前笔记」或「选择笔记」。
2. 在「发布信息」填写标题、一个分类、标签、摘要、封面和日期。首次选择会读取已有顶部属性作为默认值，之后以面板保存的数据为准。正文里的 `#标签` 不作为博客标签。
3. 首次打开或切换笔记立即生成预览。后续修改合并为约每 1 分钟更新一次，持续打字不会反复重建或不断推迟计时；没有修改时不重建。随时可点击「刷新预览」立即更新，生成过程中按钮暂时禁用，避免重复任务排队。生成期间的新修改留到下一轮，也可本轮结束后手动刷新。旧预览可继续阅读，发布按钮会等到最新内容的预览核对完成后启用。首次启动真实博客主题可能需要几十秒。右侧显示的是当前电脑博客项目的实际主题；主题在远端改过时，先同步本地项目。
4. 看过最新预览、处理问题提示后，点击「发布文章」。已有文章显示「更新文章」，网址保持不变。浏览器打开可以查看宽屏效果。
5. 发布经过整站构建、Git 提交、Git 推送、网站上线验证。看到「已推送，待上线确认」时，稍后点击「检查上线状态」。这不代表 Vercel 构建成功或失败。

更新会保留首次发布日期，同时记录更新日期；没有内容变化时不会重复创建提交。关闭面板会清理自己的临时预览，未完成的发布记录仍保留。

首次实际发布前，需要核对 Vercel 项目中的 **Production Branch**，在插件设置填写并开启「已核实生产分支」，且本地 Git 处于该分支。当前开发分支不会自动合并或推送。预览不需要开启这个设置。

## 内容和图片

支持基本 Markdown、表格、任务列表、常用数学公式、普通代码块、`==高亮==`、常见 Callout、图片双链和普通笔记双链。图片从笔记库自动定位，原图完整保留，点击正文图片即可在当前页面弹出原图。300 KiB（约 300 KB）以内且最长边不超过 1920 像素的小图，正文直接使用原图；其他图片生成最长边 1920 像素的候选展示图，只有体积严格小于原图时才采用，否则直接使用原图，不保存多余展示副本。PNG 与透明图的候选图使用无损 WebP 编码（缩小尺寸仍会减少像素），GIF 始终保留原文件与动画。

导入的本地图片在博客正文中默认居中，图片下方不显示额外提示文字；鼠标悬停显示放大镜光标，点击图片后通过主题自带的 Fancybox 弹窗查看原图，点击空白处、关闭按钮或按 Esc 返回原来的阅读位置，也可以用键盘聚焦图片后按 Enter 打开。普通段落保持原来的对齐方式。笔记中直接使用 `![[图片.jpg]]`；需要限制宽度时写 `![[图片.jpg|500]]`（宽 500 像素）。不要用 `<center>` 包住图片双链：Obsidian 不会解析 HTML 内部的 Markdown 图片。Obsidian 自身的图片居中由「设置 → 外观 → CSS 代码片段」控制，不会随文章传到博客。

本地 MP4 视频支持 `![[视频.mp4]]`、`![[视频.mp4|600]]` 和 `![说明](视频.mp4)`。自动复制原文件，显示带播放、音量和全屏控件的播放器，默认不自动播放，只请求预加载元数据。视频不压缩、不转码，播放兼容性取决于原视频的编码与浏览器（通常使用 H.264 视频、AAC 音频）。视频不能用作封面；超过 100 MiB 的文件会提前提示，因为 GitHub 普通文件不支持超过该大小，当前流程未启用 Git LFS。

已发布笔记的双链转为博客文章链接；未发布笔记显示为文字并提示。段落与块链接暂时退回文章首页。整篇笔记嵌入、Dataview/Tasks 查询、其他视频格式/PDF/SVG 嵌入、缺图或无法渲染的公式会阻止发布，需要先整理成支持的静态内容。代码示例中的这些语法不作转换。

博客项目中仍会生成一份公开稿和引用图片，供 GitHub/Vercel 构建使用；程序自动管理，不需要手工复制。笔记库中的原文和原附件不会被插件修改。旧博客文章保持原状。

## 草稿、记录与恢复

- 发布信息与文章编号保存在 `.obsidian/plugins/blqblog-publisher/data.json`，上一份有效数据保存在 `data.previous.json`。请定期在插件设置「导出 JSON」备份；这不是笔记正文备份。
- 下拉框保存所有文章记录。插件运行时，笔记改名/移动会更新关联；删除笔记不会删除线上文章。缺失的笔记可手动重新关联，保留原网址。
- 「下架」会确认后移除该文章的博客输出，保留原文、发布信息和 Git 历史。重新发布沿用原网址。第三方缓存与他人下载不受此操作控制。
- Git 暂存区有内容、本地有未推送提交、分支落后或分歧、博客项目有未提交修改时，发布会暂停。无关的未跟踪文件不会加入文章提交。
- 推送失败后不要删除 Git 提交。点击「继续操作」续传；重启面板会读取本地操作记录。已经推送但未确认上线的文章点击「检查上线状态」。
- `cache/obsidian-publisher/operations` 保存未完成操作与恢复所需输出，完成发布前不要删除。操作日志属于本机，不会自动提交到 Git。
- 迁移电脑时，复制笔记库与博客项目、安装 Node 和 pnpm、恢复插件数据，然后更新设置中的路径。也可以使用「迁移导入」，显式把备份记录关联到当前库与博客目录；冲突不会自动覆盖。

## 开发与安装

需要 Node >= 22，博客项目已执行 `pnpm install`，Git 使用本机已有登录信息。

```powershell
pnpm publisher:build
pnpm publisher:test
pnpm publisher:install E:\1me
```

安装只更新 `manifest.json`、`main.js` 和 `styles.css`，保留已有数据，并备份旧程序文件。安装包在 `cache/obsidian-publisher-plugin`；转换和发布引擎位于已配置博客项目的 `scripts/obsidian-publisher`，移动项目后要更新插件设置。

本地预览服务只监听 `127.0.0.1`，网页本身没有发布接口。插件退出会停止自己的预览；正在进行的发布保留可恢复记录。第一版只面向这台电脑，网站整体图片加载优化另行处理。
