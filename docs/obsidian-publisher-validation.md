## 独立审阅与修复

一次独立整分支审阅提出六项问题，均补充失败回归后修复：

| 问题 | 修复与证据 |
|---|---|
| 并发 Git 操作可能夹带文件或提交 | 独立临时索引、比较并更新分支引用、只推送记录的提交 SHA；保留无关暂存内容 |
| 未跟踪的主题/构建文件可能只在本机出现 | 对实际镜像的构建输入检查 Git 跟踪状态；无关 AGENTS.md 等文件仍允许保留 |
| 操作结束后字段仍被禁用 | 修正真实视图操作生命周期；测试检查完成后五个元数据输入仍可编辑 |
| 高亮可能改坏链接 URL | 保护链接与引用定义，保留嵌套加粗；转换回归通过 |
| HTTP 成功不代表最新预览 | 页面版本标记、HTTP 内容核对和 iframe 消息确认共同校验 |
| 更新缺少 updated 日期 | 真实内容更新生成日期；保留原发布日期与无变化时的幂等行为 |

另补充停用期间移动笔记的启动检查，以及仅清理自身预览目录、保留发布操作记录的测试。没有延期的审阅问题。

## 实现取舍与边界

1. 复用现有目录，以本地功能分支隔离开发，没有另建工作树。代价：正式使用前需要将开发代码并入生产分支；切换回尚未包含发布引擎的旧分支时插件无法启动引擎。
2. Windows 下以 PowerShell 和同等 Git 命令记录执行证据，临时工作区放在已忽略的 cache 中。摘要保存在本文件；截图和完整测试日志位于 `cache/obsidian-publisher-delivery`，清理缓存会移除这些本地证据。
3. 按用户审阅后首次发布的约定保留本地版本。代价：实际 GitHub 凭据、Vercel 生产分支及真实域名部署尚未验收；「已核实生产分支」保持关闭。
4. 原生 Obsidian 和浏览器验收由主执行者完成，独立审阅者检查代码与边界。真实应用的重载、保存和预览有证据，但不将其表述为线上部署成功。
5. 手机、多用户发布、自动迁移旧博客文章、全站加载速度优化均按约定排除。第一版不承诺这些工作流。

## 首次正式发布前

用户先检查已打开的 CD8 预览和面板交互，再核实 Vercel 的 Production Branch、将开发代码并入并同步该分支，填写插件的生产分支设置。首次真实发布仍使用同一篇笔记、同一稳定网址，并在推送后验证域名上的唯一版本标记。
